This closes the gap recorded in MEMORY.md since Phase 4. Until now,
immutability rested on there being no code path that issues an update,
plus validators that reject a write whose shape or sign is wrong. A
validator can only judge the resulting document, so a self-consistent
update still succeeded. Under this profile the application's own
credentials lack the update and remove privileges on ledger_entries and
transactions, so such an update fails with Unauthorized regardless of
what the application code does.
